         **INTRODUCTION**

         

         This is the C68 Basic C\-Port support library\.  

         

         NOTE\.  If anyone is produces more complete documentation for some \(or all\) of these routines, then please feed them back for inclusion into later releases of C68\.  Also please feed back any errors that you notice in the documentation\.

         

         

         **LIBRARY ROUTINES**

         

         The following is a list of all the SuperBASIC keywords that are \(or might be in the future\) handled by this library\.  It is in alphabetical order of the SuperBasic keywords\.   For each keyword, there is an indication of what happens at the C level and information is given on how it is handled by CPORT and/or this CPORT support library\.   If there is no information given for a keyword that means it is not \(yet\!\) handled\.

         

         C library names that start with SB\_ are support routines that are generated by CPORT due to use of a particular keyword at the SuperBASIC level\.  The name of the keyword will follow the SB\_, but with the case changed and any trailing $ or % symbol removed\.

         

         C library names that start with CP\_ are generic routines that are inserted by CPORT to carry out functions that do not relate directly to individual keywords\.

         

         Finally there are C library names that begin with an underscore \(typically \_SB\_\)\.   These are routines that are not called directly from the users original source, but as a result of macro definitions in the CPORT\_H header file\.

         

         In many cases it will be seen that many of the calls of the form SB\_xxxx are mapped onto a library routine with a name of the form \_SB\_xxxx that apparently takes the same parameters\.  This is has been done so that 'cast' operators can be used within the macro definition for numeric parameters that need to finish up as 'int'\.  If the user has not typed many of the SuperBasic variables they will have been converted as 'float'\.   The use of a macro definition containing a cast will instruct the compiler to do the relevant conversions\.

         

         It is highl recommended, however, that you go through the generated source and wherever possible change such variables to 'int' or 'short' as MUCH more effecient code will be generated\.  The **CfiX** utility will help with this as it can automatically convert floating point constants to integer constants where appropriate\.

         SuperBasic:    **INPUT**

         C:    **converted**         \(but see below\)

         The INPUT statment is converted by CPORT to calls to the **fscanf\(\)** function in the standard C library\.  The **fscanf\(\)** routine differs significantly in behaviour from the superBasic INPUT routine\.

         

         You are better of if you convert all these calls by replacing the **fscanf\(\)** keyword with the **SB\_Input\(\)** keyword \(this is done automatically by **CfiX**\)\.   This emulates the INPUT routine far more exactly\.  Its syntax is:

         

             **int**    **SB\_Input\( FILE \* fp, char \* formatstr, \.\.\.\)**

         

         where '**formatstr**' is as set up by CPORT\.  Note that although this format string looks very similar to that used by **fscanf\(\)** is does not support the same range of options \- only those that CPORT generates\.  The valid options are:

             %d    Read a short decimal number

             %ld  Read a long decimal number

             %f    Read a 'float' floating point number

             %lf    Read a 'double' floating point number

             %?    Read a Boolean \(long int\)

             %s    Read a string

         If the input channel is a console device then any other characters in the format string are merely echoed\.   If the input channel is not a console device, then other characters in the format string are ignored\.
